# ربط نموذج مِيزان بقاعدة D1

## ما أُنجز بالفعل في Cloudflare

تم إنشاء الجداول التالية داخل قاعدة D1 الحالية `mizan-orders`، من دون تعديل جدول `orders` أو بياناته:

- `contact_requests`: طلبات التواصل والاستشارات.
- `contact_request_limits`: حدّ مؤقت لمنع الإغراق؛ يُحفظ فيه تجزئة عنوان IP لا العنوان الخام.
- فهرسان لتسريع عرض الطلبات حسب تاريخ الإنشاء والحالة.

تم التحقق من نجاح أوامر الإنشاء عبر Cloudflare API. حجم القاعدة ازداد بمقدار 16 KB تقريبًا بسبب إنشاء الجدولين والفهارس.

كما أن ربط قاعدة البيانات باسم `DB` موجود في Production، وقد أضفت الربط نفسه بنجاح إلى Preview عبر Cloudflare API. لم أغيّر بقية إعدادات البناء أو فرع الإنتاج.

## الملفات الموجودة في هذه الحزمة

- `functions/api/contact.js`: واجهة Pages Function على المسار `/api/contact`، وتتحقق من المدخلات والموافقة، وتحدّ من الطلبات إلى 5 لكل IP في الساعة، ثم تحفظ الطلب في D1.
- `contact-api.js`: يربط نموذج الموقع بالواجهة الخلفية ويلغي سلوك النسخة التجريبية القديمة التي تفتح WhatsApp أو البريد.
- `migrations/0001_contact_requests.sql`: نسخة موثّقة من مخطط الجداول (استخدم `IF NOT EXISTS`، لذلك لا يعيد إنشاء الجداول الموجودة).
- `INDEX-CHANGES.txt`: التعديلان الصغيران المطلوبان في `index.html`.

## ما عليك فعله يدويًا في GitHub

المستودع: `moncefxb/siteweb`، الفرع: `Mizan`.

1. افتح المستودع وأنشئ فرعًا جديدًا باسم `feat/contact-form-d1` من `Mizan`، حتى تختبر التعديل قبل دمجه.
2. من **Add file → Create new file** أنشئ `functions/api/contact.js`، والصق محتوى الملف المطابق في الحزمة.
3. أنشئ ملفًا جديدًا في جذر المشروع باسم `contact-api.js`، والصق محتواه.
4. افتح `index.html` وعدّله وفق التعليمات الدقيقة في `INDEX-CHANGES.txt`.
5. احفظ التعديلات في الفرع الجديد.

مهم: يجب أن يكون مجلد `functions` في جذر المشروع، بجانب `index.html`، وليس داخل مجلد آخر. إعداد Pages الحالي يستخدم جذر المشروع كمجلد النشر.

## إعداد Preview في Cloudflare

تمت إضافة ربط D1 باسم `DB` إلى بيئة Preview بنجاح، مع الإبقاء على ربط Production إلى قاعدة `mizan-orders`. لا تحتاج إلى إعادة هذه الخطوة. عند إنشاء فرعك وإضافة الملفات، سيُنشئ Cloudflare نشر Preview جديدًا تلقائيًا. بعد نجاح الاختبار، ادمج الفرع في `Mizan` ليُنشر على الموقع الإنتاجي.

## الاختبار والتحقق من الطلبات

1. افتح رابط Preview، وجرّب إرسال طلب تواصل ببيانات اختبار غير حقيقية.
2. يجب أن تظهر رسالة نجاح بعد الحفظ، لا أن يفتح WhatsApp أو البريد.
3. من Cloudflare → **D1 → mizan-orders → Console** نفّذ:

```sql
SELECT id, full_name, phone, subject, status, created_at
FROM contact_requests
ORDER BY id DESC
LIMIT 20;
```

لا تعرض `message` على شاشة عامة؛ فقد يكتب المستخدم معلومات شخصية فيه.

## حدود الحل الحالي وملاحظات مهمة

- النموذج يحفظ الطلبات في D1 فقط؛ لا يرسل إشعار بريد أو WhatsApp إلى المكتب. يلزم إعداد قناة إشعار منفصلة لاحقًا.
- لا تضع أسرارًا أو مفاتيح API في ملفات JavaScript العامة.
- النموذج يطلب عدم إرسال معلومات القضية السرية أو الوثائق. لا تستخدمه لاستلام ملفات قانونية.
- حدّ الطلبات الحالي 5 لكل عنوان IP في الساعة. عنوان IP لا يُخزّن في سجل الطلبات؛ تُحفظ تجزئته فقط في جدول الحدّ.
- الطلبات الجديدة تبدأ بالحالة `new`. يمكن تحديث الحالة من D1 Console إلى `contacted` أو `closed` أو `spam`.
- ضع سياسة خصوصية/احتفاظ واضحة، واحذف الطلبات بعد انتهاء الغرض منها وفق التزامات المكتب القانونية.
- لم يتم نشر تغييرات في GitHub لأن اتصال GitHub المتاح رفض الكتابة بخطأ `403 Resource not accessible by integration`.
